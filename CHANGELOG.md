# **Changelog**

All notable changes to Skales will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),

and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## v12.9.32 - Husky

**A release that answers once, shows what it is doing, and fits the window it is in.**

Skales asks a lot of questions - may it run this, may it click that, may it send a picture to a model that cannot see one - and this release is about what happens around those questions. One yes can now cover a whole tool or the rest of a session, on the computer and on the phone alike, and a card that comes back says why it is back instead of looking like a button that did not work. A browsing run that reaches something binding parks on the question and carries on after the answer, and a click addressed by number raises the same question as a click addressed by name. A picture bound for a model without eyes is announced before it goes, with a way to switch and a way to continue.

The second half is the surfaces themselves. The Code window takes its colours from the theme you picked and keeps its own shape, its model picker scrolls at any window size, its panels survive a reload, the document you are reviewing is the main part of its column, and the browser sits beside the transcript as a panel that shows the run's own pictures. Opening a long conversation happens once, with the row saying so, and the days in the conversation column fold away. Iris wears the theme too. Around all of it: a sub-agent that reads your code is told it is yours, every typeface and piece of artwork Skales ships is named with its licence, and a fresh installation lands on the free built-in provider instead of one that needs a key.

### Added

- **Code can repeat an objective with `/loop [5m] <task>` until verification succeeds.** The loop keeps its state in the session, resumes after restart, carries review findings into the next attempt, and uses the existing goal, approval and cost machinery. Stop also ends an interval wait. A requested phone notification follows verified completion through the paired-device channel.

- **A read-only diagnosis for the WhatsApp bridge, in Settings, Integrations.** One button answers the questions that decide what to try next: is the bridge process alive and what state is it in, which build is loaded, which build is wanted and who chose it, is an automatic pin still in force, how far a recovery got, and what class the last failure was. It carries no phone numbers, no contacts, no tokens and no message text, so the state of a channel can be read without going anywhere near what is stored for it.

- **Every sub-agent role now says what it runs on, and lets you say otherwise.** A dispatched helper has been able to run on a different model from the conversation that sent it since the roles shipped - the reading roles default to a cheap local one so a handful of errands cannot cost more than the conversation that ordered them - but nothing in the app ever said so. Settings, Goal, under the role picker, now opens a row per role: the model that role will actually use, and where that answer came from - set here, the role's own default, or inherited from the conversation. Each row can be set to the conversation's model, to a cheap local one, or to a model you name, and a row you leave alone keeps the role's default. It reads and writes exactly the setting the dispatcher reads, so the row cannot say one thing while a run does another.

- **A licences page inside the app, for the people who will never see the repository.** Settings, About now carries a button that opens the whole third-party notice document, set as a document rather than as a wall of plain text: headings, lists, and every licence text in full. Two of the licences behind what Skales ships ask for exactly this - that the copyright lines and the terms can be easily viewed by whoever received the copy - and a file in a source tree is not that for somebody who installed an app. It reads the copy that travels inside the package, so it works with no connection and on a machine that has never been near a checkout. You can also reach it by name from the command palette.

- **Every typeface and every piece of artwork Skales ships is now named, with its licence.** The notices listed four of the eight typefaces that travel inside the app - the handwriting and storybook faces you can pick for chat bubbles, and the colour emoji font, were shipped without a word. All eight are listed now, each with its author and its source. The animated emoji get a section of their own: they are Google's Noto Emoji artwork, they are handed out from Skales' own address rather than linked to Google's, and Creative Commons asks for the creator, the source and the licence to travel with every copy, so all three do. A check now reads the folder itself before every release, so a face dropped in without a notice fails the build instead of shipping unattributed.

### Fixed

- **Idle Code loops no longer reread every conversation each minute.** Recovery uses the existing session index, keeps restart recovery, and skips active or not-yet-due work before loading transcripts. The Code status poll reads an idle session once.

- **WhatsApp contact questions read the current saved contacts.** The assistant can look up the contacts shown in Settings, including the owner and each permission, instead of searching workspace files or guessing who is saved. Sending to yourself uses the account number separately from its display name.

- **Code roles stay attached to long coding runs and start from the landing composer.** The reviewer no longer times out after thirty minutes or treats an interrupted coder as finished. Empty-task guidance clears while typing, rejected tasks stay in the composer, and active roles use the shared run indicator. Architect and reviewer costs now count toward the same session ceiling as coding turns.

- **Model pickers identify failed live fetches and keep their merged lists in order.** Codex falls back to an explicitly labelled curated list with the fetch error; custom entry stays first, duplicate model IDs disappear, and late responses cannot overwrite a different provider's list. Existing per-role subagent choices continue through the shared dispatcher.

- **Repository searches agree across the built-in and ripgrep engines.** Hidden and git-ignored source files remain searchable while dependency folders and protected paths remain excluded. Single-file hits carry their filename, later pages remain reachable beyond 5,000 matches, and relative glob paths follow the session's working folder.

- **A WhatsApp recovery no longer announces a build it did not load.** When a file died inside WhatsApp's own page code, Skales restarted the bridge on the last build known to carry files - and then reported that build as soon as the client was back, without ever asking which build it had come back ON. With a build pinned by hand in Settings, the restart loaded the pinned one again, so the answer named a build the bridge was not running: the same outage, described as a recovery. The bridge is now asked for the build it is really on, and a recovery is only reported when that answer matches what it asked for. A build you pinned by hand is not moved behind your back either: a recovery may step over it for the client it is starting, it says so in the same breath, and the next restart is back on your pin.

- **Emptying the WhatsApp Web build field really does hand the choice back to WhatsApp.** The field held your own pin, but a build that a previous self-heal had settled on lived somewhere else - so clearing the field left that automatic pin in force and the bridge kept starting on it, while the panel showed an empty setting. Saving an empty field is now its own instruction, carried out by the process that owns that record and applied even when the bridge is not running at the time. A self-heal that happens afterwards still counts.

- **A file that fails twice marks both builds, instead of quietly leaving the second one blameless.** The first failure was written down; the retry on the fallback build went straight to the outer error handler, so a build that had just failed the same way stayed on the books as untried - and could be chosen again on the next send, over and over. Every attempt is now booked against the build it actually ran on, read fresh before each send so a restart in between cannot move the entry, and a candidate that fails stops being a candidate. There is still exactly one retry and one restart per file.

- **A message WhatsApp never acknowledged is no longer recorded as one that went out.** A send with no acknowledgement inside the short wait is reported as queued, which is honest - but the build memory behind the self-heal wrote it down as proof that files travel under that build, so the next outage could fall back to a build nothing had ever confirmed. The memory now separates handed over, accepted and confirmed, and only a confirmation makes a build a proven fallback. A late acknowledgement counts for the attempt that earned it, on the build that sent it, and a queued file is never sent a second time.

- **The WhatsApp panel tells the build you asked for apart from the build that is loaded.** Saving a build stores a setting; it does not reload the running bridge. The panel now says both, says which of the two is in force and on whose authority, warns when a restart is what applies the setting, and says when the named build has never been seen on this machine - a pin whose page is not on disk only makes WhatsApp serve the current build again, and that used to read as a pin that had taken.

- **The pictures a browsing run showed stay with the conversation after the run ends.** Closing the browser emptied the whole screenshot folder, and every step that had said "here is the page" in an older conversation was left pointing at a file that was no longer there - a broken image in a transcript nobody could repair. A run of more than fifteen steps lost its earliest pictures the same way while the conversation was still open. A picture is now written down as history the moment its path goes into a step's answer, and a close removes the live view's own names and nothing else. What a cleanup may take is only what nobody was ever shown: bytes left behind by a capture whose step then failed. The history is bounded, but the bound falls on the oldest conversations rather than on the one being read, and it survives a restart because the record sits next to the pictures instead of in the running process. A phone watching a run gets the same pictures from the same place once the run has ended, still flagged as no longer live.


- **A picture a model writes straight into its answer now appears, as a real file.** Some models answer with the image inlined in the text rather than as an attachment. The renderer dropped those on the floor - correctly, because an inlined document is how a script arrives dressed as a picture - so the answer showed an empty space and the reason was nowhere. The four formats a browser can only ever decode as pixels are now let through, and not painted from the text either: the bytes go to the same place an attached picture goes, and what is drawn is the ordinary file. So it survives a reload, a tool can open it, the conversation file does not swell by a megabyte of base64, and the same picture twice is one file on disk. Everything else that arrives this way - drawings that can carry script, whole web pages, anything that is not one of the four - stays blocked, one step earlier than before. The coding window draws it through the same wire as the chat.

- **A message sent to a coding session keeps its own name all the way to the transcript.** Every line that goes into a running session is given one id at the moment it is sent, and that id now travels with it: into the queue, through the fold that turns several waiting lines into one turn, onto the turn as it is written down, and back out again when a phone opens the session. Until now a phone could be told that its line had been accepted but had no way to tell which turn in the history it had become, so it counted user turns instead - and a sentence typed at the computer while a phone message was still on its way was counted as the phone's own. The same id the phone already sends with the message is the one it finds on the turn; a line typed in a window gets one of its own. Older conversations, whose turns were written before any of this, are read exactly as before.

- **The Code window's history opens in front of the panels, not behind them.** On a small window - a phone browser reaching the computer over the network, a window dragged down to a strip - the review, browser and preview panels lie over the whole body. The session history the burger opens had no layer of its own, so the button worked, the menu was there, and every tap on it landed on the panel above instead. In that lage the history is now a drawer in front of those panels, and the way back out of it is the burger, the Escape key, or a tap beside it.

- **The Code history closes itself once you have picked from it, on a small window.** As a drawer it lies over the session, so leaving it up after a row was tapped would cover the very thing it was used to choose. It now steps out of the way when a session is opened or a new one is started - and only there: as a column on a wide window it takes nothing away and stays where it is.

- **A small window no longer pushes the composer off its right edge.** With the history open at 414 pixels wide and 446 high, the column and the transcript's own floor added up to 500 pixels and the send button was outside the window. The history no longer stands beside the transcript there, so the transcript keeps the width it had and the composer stays whole - at 414, 360 and 320 pixels alike. In the taller narrow layout the history strip also keeps a floor, so it holds rows instead of being crushed to a line between its own heading and footer when three panels are open.

- **The browser pane in the Code window can be dragged to the width you want, and remembers it.** The review and preview panes beside the transcript have had a draggable left edge for a long time; the browser pane, opened on the same split, was stuck at the width the stylesheet picked. It now carries the same handle - mouse or arrow keys - and the width it was dragged to comes back with the next window. Where a pane is an overlay or a stacked row rather than a column - a small or short window - no pane offers a drag edge any more: the handle there moved nothing and said otherwise.

- **Skales Code inside the app no longer covers the navigation on a narrow window.** The coding surface is a fixed layer, and on a phone-sized window it started at the very top of the frame - over the app's own header, which is the only way back to the rest of Skales from there. It now begins below that header, measured off the header that is actually on screen rather than a number typed into a stylesheet, so it is right in every navigation shape and at every text size. The standalone Code window has no such header and still uses the whole frame.

- **The two wider answers on a permission card are offered in Flow too, not only in Skales Code.** A yes given in the coding window - allow this tool for the rest of the session, or stop asking for the rest of the session - was already honoured in Flow, because both cards read the same record. It simply could not be GIVEN there: Flow's card offered only "allow once" and "allow this kind of action", so the same answer was reachable from one surface and not the other. Both buttons now sit on Flow's card, with the same words and the same reach, and they appear under exactly the same condition: only where every question on that card may carry a standing yes at all. Purchases, logins, exports and one-way clicks still ask every single time.

- **The licence no longer promises an address it does not carry.** Its opening line said the licensor's name, address and contact details were in section 12, and section 12 gives a name and an email. The line now says what is there. Both the English and the German text are affected, both are corrected, and nothing else in the agreement changes - it remains version 1.2.

- **A group of sub-agents works where the call said to work.** Sending several helpers out in one go takes the same settings at the top of the call or on each helper, and the top of the call was being thrown away: "all of you work in the project folder" gave every one of them a private scratch folder instead, so each then read the user's own repository from outside its own boundary and was blocked - on the errand that exists for exactly that reading. What the call says once now applies to every helper that does not say otherwise, for the folder, the model, the role, the tools and the step budget. A helper that names its own still wins, and a call that names nothing behaves exactly as before.

- **A goal on a web page that needs two approvals asks for both, instead of stopping after the first yes.** Working a page towards a goal stops and asks before anything binding, and Skales ran exactly one round of asking: after your yes it took whatever came back as the final answer. A form with a binding step in the middle and another at the end therefore came back still waiting, with nothing to show for the yes you had already given, and the only way on was to ask for the same thing again. The step now asks as often as the work genuinely stops, up to five times, and each one is a card you answer. A no ends the run exactly where it always did, and pressing stop stops.

- **Saying no to a browser step no longer locks the browser until Skales is restarted.** A run that opened a browser claimed it, so a second run could not drive the same window out from under it - and that claim was never given back when the run ENDED without unwinding, which is what happens when you refuse a browser step or when a run fails outright. Every browser action after that was refused with "the browser is in use by another run", including the one that closes it, for as long as the app stayed open. A claim is now only honoured while the run behind it is actually running; one left by a finished or failed run is handed on, and closing the browser is never refused for want of a claim.

- **Picking an option from a dropdown is one step, and it actually sets it.** When Skales works a page towards a goal, choosing from a dropdown opened the list and stopped there - and the step after it was decided from a reading of the page taken before the list was open, so the option was not in that reading and there was nothing to aim at. The list opened and the run moved on with the dropdown untouched. A real dropdown now hands over its own choices with the rest of the page, so the step names the option and sets it in one act, and Skales reads the control back afterwards rather than reporting a success it did not have. An approval card raised on such a step names the option, not just the control, and answering yes sets that option. A dropdown a site draws for itself out of buttons is still opened first, because until it is open its options are not on the page to be named.

- **Typing into a search box on a big site works, and stops taking half a minute to refuse.** Before writing anything, Skales checks that the field it was told to write into is really the one holding the keyboard - the check that stops text landing in the wrong box. On sites that swap a search box for its live version the instant you click it, the element that was addressed is gone by the time that check runs, so the check waited its library's full thirty seconds for an element that would never come back and then refused a click that had actually worked. On Wikipedia that was thirty seconds per attempt, every time. The check is now bounded to two, and when the element has been replaced it identifies the field by its name instead - the same name the request chose it by - so the text goes where it was meant to. A field with no name, a different name, or no editable field in focus at all is still refused, and still without writing anything.

- **Skales IQ stops claiming to be ready on a machine whose trial was never started, or has ended.** Skales IQ is the one provider you never paste a key for - the app fetches a trial token and gives it back when the trial runs out - and two places read "no key field on the card" as "needs nothing at all". So the agent editor listed it as configured on a fresh install, and the Iris window stayed silent instead of showing the settings hint every other unconfigured provider shows. Both now ask the same question the chat turn asks: is there a token. Nothing changes on a machine with a running trial.

- **A long conversation folds itself again, including one you reopened from your history.** Skales folds older parts of a chat to keep it inside the model's window, and every one of those folds was deciding on the wrong number: it weighed the list of messages it happened to be holding, while the request that actually goes to the model carries the instructions, the tool descriptions and the working state on top of that list - far more than the conversation itself on this product. In a chat opened from the history the two numbers were sixty-two tokens against nearly forty thousand, so no automatic fold could ever fire there, at any setting, and the window quietly filled until a turn was refused. The fold now decides on the size the model's own provider reported for the last request, and on the estimate of anything added since, whichever is larger. Nothing about when or how much it folds has changed - only what it looks at.

- **A coding session started from your phone opens on the model and the effort you picked there.** The phone could choose both, but the computer read neither: the session opened on whatever this machine happened to be set to, spent its first turn - the expensive one - there, and only then could be moved. The choice now travels with the start and is written on the session before the first word is sent. A phone that names nothing, or an older one that cannot, starts the session exactly as before.

- **A permission card on your phone offers the wider answers the computer will actually honour.** The phone was sent a tool name and a sentence, which is enough to answer once and not enough to answer any wider - so the two broader buttons never appeared there, and a session permission given at the desk was invisible from the sofa. Each waiting card now carries what it is about: the tool, why it stopped, what a standing yes would cover, and which reasons this session already allows for that tool, so the phone can say why a question is back instead of looking like a button that did not work. The two broad buttons appear only when the computer itself says every waiting question may carry a standing yes, and the answer is redeemed through the same one place the computer's own card uses - a purchase, a login, an export or a click with no way back still asks every single time.

- **A picture sent from your phone to a model that cannot read one now asks the same question the chat window asks.** The turn was written down and parked exactly as on the desktop, but the phone was handed an error instead of the question, so a conversation with an image in it simply stopped. The card travels as a card now: switch to a model that reads images, or continue and let your Vision Provider describe it. Continuing starts the turn that is already written rather than sending a word, and the answer comes back the same way every other answer does, with its checklist, its goal card and its price.

- **A phone watching a browser run can be shown the pictures the run is taking.** The panel on the computer draws the agent's own screenshots with the line that says what each step was; a phone had no way to ask for them and saw the run only once it was over. The pictures now travel over the same paired-device path a picture in the history takes, newest first and capped at the same twelve the panel keeps, and only the ones the phone has not already seen are sent. They live for the length of the run, as they do on the computer.

- **Four languages write the permission reasons the way they are written.** The lines that say why a step stopped - it reaches outside the project folder, it looks destructive, it touches infrastructure Skales does not know - were stored without their accents and tone marks in Portuguese, Vietnamese, Turkish and Croatian, in both the coding window and Flow. A Vietnamese sentence without its tone marks is a different sentence; all of them are spelled properly now.

- **A message you queue in one conversation is sent there, once.** Lines typed while an answer was still running belonged to the window rather than to the conversation: switching to another chat carried them along, while the chat they were typed in had also kept a copy - so coming back showed more waiting messages than were typed, and the model was asked each of them twice. The waiting lines now stay with their own conversation. Switching away puts them away, the chat you open shows its own, and coming back finds exactly what you left, once. Nothing goes out into a conversation it was not typed in, including a message already on its way when you switch - it returns to its own chat and waits there.

- **One yes can now cover a whole tool, or the whole session, and the card says what changed when it comes back.** A permission card in Skales Code offered a yes for exactly one kind of stop, so being asked about the same tool a second time for a different reason looked like the button had not worked. The card now names the difference in one line - what you allowed, and what this is instead - and offers two wider answers next to the old one: allow this tool for the rest of the session whatever stops it, or stop asking for the rest of the session altogether. Both end with the session and are written down on it, so reloading the window does not ask again. Neither lifts a single guard: paths still have to resolve inside the folder you bound, the commands that cannot be undone are still blocked outright, and purchases, logins, exports and one-way clicks still ask every single time - so the wider answers are offered only on a card where every question may carry a standing yes at all.

- **A permission answered on your phone reaches as far as the button said.** The phone could say "allow this for the session" and the computer heard a single yes, so the very next step asked again. It now carries the same four reaches the computer's own card offers, including the two new wider ones. A computer too old to hold a wider answer is never sent one: the phone keeps the narrow yes and says so, rather than promising something that quietly did not happen.

- **A session no longer records permission for tools you were never asked about.** Approving a step approved the tools that had actually stopped, and also quietly remembered every other tool in the same step - including ones that never ask, such as updating the task list or listing a folder. The session file claimed consent that was never given. Only the tools the card actually asked about are remembered now.

- **Settings says where the global safety mode stops.** Skales Code runs on the mode you pick when a coding session starts, and a machine set to Advanced or Unrestricted deliberately does not reach into it. Nothing said so, so the setting that acts and the setting you see were two different things. The Safety Mode panel now spells out what Auto means inside a coding session and that this panel does not lengthen or shorten that leash.

- **A sub-agent that reads your code is told it is yours, and one that declines says so instead of showing a tick.** A sub-agent sent to read the sources of your own project was handed the errand and nothing else, so it fell into the standard caution about somebody else's material and refused - politely, three times, for a six-figure token bill, while the run that started it read the very same files minutes later. Every sub-agent is now briefed with the same sentence its parent run carries: this is the user's own work, they are the author, reading and auditing it is the task. A refusal is recognised on the step it happens and ends that run there rather than paying for more of the same sentence, and the sub-agent card counts a child as done only when a result actually arrived - otherwise the row says nothing was delivered, names the reason beside it, and the answer passes that reason on to you. A child whose provider reported no price now reports what its tokens cost from the same price table the rest of Skales uses, marked as an estimate, instead of "price not reported" next to a number it already had. Reading roles also run on a cheap model by default instead of inheriting the conversation's, each role can be pointed at a model of your own in settings, and the step budget on a sub-agent call is described as what it is - a floor, never a cap.

- **The closing report of a long coding run counts what the run did, and ends on what it found.** A run that had written a single file closed with "4 files changed (+931/-0) on main" - the working tree's own state, including changes that were there before the run started and were never its work. The report now names what THIS run wrote, split into the project's own code, a document it was asked to produce and a by-product of a tool, and says separately how much of the tree was already changed beforehand. The last thing it says is the outcome of the run together with what that outcome does not cover; the numbers stand above it rather than in its place.

- **A cut-short search, listing or command output can be continued where it stopped, and a write the project rules paused keeps what it was carrying.** Reading a long file always said how to read the rest; a long grep, glob or folder listing only said "narrow the pattern", which is no help when the pattern was right - each of them now reports where the next page starts and takes that offset back, and a long command or script output is written out in full so the rest can be read with the ordinary file reader. When a project's own rules apply to a file being written for the first time, the pause used to paste those rule files into the result whole, twice over, in the room the answer needed: it now names the files and quotes the lines that bear on the target. The content of the paused write is held rather than thrown away, so the retry no longer sends the same fifteen kilobytes a second and third time.

- **A message typed while a turn is running is judged the same way wherever it was typed.** Three places in the chat window decided what happens to an outgoing line - queue it, send it anyway, say the queue is full - with three conditions that had drifted apart and could not be compared by reading. They now ask one place, which is the one that already had the tests. Nothing about what happens changed; it is simply the same answer in all three.

- **A picture sent to a model that cannot read one no longer ends the turn with a number.** Some model names promise that they read images while none of the servers reachable behind that name actually take one, so the request came back refused and Skales repeated the bare status - which read as "this model is gone" and sent people to replace a model that works. Skales now recognises what was refused, says that it was the picture, and carries the turn on: your Vision Provider describes the image and the model answers from that description, which is marked as a description so it never pretends to have looked. The refusal is remembered for that model, so the next picture takes that route straight away and a conversation with an image in it can be reopened and continued without changing model.

- **Before a picture goes to a model that does not read pictures, the conversation says so and asks.** The card names the model, explains that the image will be described by your Vision Provider and passed on as text, and offers two things: switch to a model that reads images, or continue. Switching opens the model picker and keeps the conversation exactly as it is; continuing runs the turn you already typed and does not ask again for the rest of that conversation. It appears in the chat window, in the Code window and on a turn sent from your phone, because all three now hand pictures to the same place.

- **The Code window reads attached images the same way the chat does.** It handed every picture straight to the session's own model, so an image in a coding session was refused outright wherever the chat would quietly have had it described first. Both windows, and a turn arriving from your phone, now take the same route.

- **A file path written in an answer is a link again.** In the Code window a path in an answer is meant to be clickable - that is how you get from "I changed `src/app.ts`" to the file itself. The markdown renderer stopped telling the window which code spans were written inline, so the test for it was never true and every path in an answer had quietly become plain text; the only clickable file names left were the ones the tool lines draw.

- **A Markdown file clicked in an answer opens on the page, not on an empty diff.** Clicking a `.md` path in the Code window put it in the review panel on whichever tab had something in it, which for a file with no pending change was its raw text - even though the panel renders Markdown properly one tab over. A Markdown file now arrives on that rendering. Pages, images and PDFs still open in the preview panel, where they are served and run.

- **The review card for a file that is not there says so.** A path that had been deleted, or that the panel was refused, was drawn as an empty card reading "nothing to review" above "0 files" - technically each true, together unreadable. Each tab now names which of the three it is: the file is gone, it cannot be read, or the read was refused and why. The empty-list sentence and an open card for one named file are no longer both on screen.

- **The document you picked is the main part of the review column, and it scrolls by itself.** The column was a scroller with a flexible stack inside it, so the document gave way first and was then capped against the height of the SCREEN to have any room at all - in a panel the user can drag narrow, in a window that can be four hundred pixels tall. The file list, the branch block and the commit block are fixed rows around it now, each with its own scroller, and the document takes the rest. Keep and Revert stay below it whatever the file's length.

- **A block inside the review panel stops behaving like the panel itself.** The branch block inside the review panel carries the same name in the stylesheet as the panel it sits in, so the rules written for a whole panel in a small window reached it too: in a short, narrow window it filled its own panel from top to bottom and buried the file list, the document and the commit box underneath it. The rules now name the panels themselves and nothing inside them.

- **The panes of the Code window are still open after a reload.** The review panel, the preview and the browser were opened afresh every time the window was, whatever had been on screen a second earlier. All three are remembered together now, per window, like the terminal's height and the panel widths beside it.

- **Clicking a long conversation opens it once, and the row says so while it does.** Opening a big chat could take long enough that nothing on screen had changed yet, so the natural thing to do was click again - and every click started another full read of the same file, each one slowing down the one before it. The row you clicked now shows straight away that it is working, a second click on it does nothing because it is already the request you made, and clicking a different conversation drops the one in flight instead of queueing behind it. Opening a conversation also stopped re-reading every other conversation on disk to notice that one of them had a new message: it refreshes the row it changed.

- **When the machine runs short of memory, Skales gives up the local model rather than letting the system pick.** On a machine with a local model loaded, the system had been choosing what to shut down when memory ran out, and what it kept choosing was the engine every Skales window talks to - so the whole app went blank while the model kept its weights. Skales now watches for the machine getting close to that line and stops the local model server itself, says so in the Skales Local tab, and leaves it down for a few minutes so the two do not immediately fight over the same memory again. Pressing Start there brings it straight back. The engine also has a ceiling on how far it may grow, well above what it uses.

- **A conversation opened from a link costs what the same conversation costs when Skales reopens it for you.** Reopening a chat renders the most recent part of it and says so, with a button to bring the rest back. Arriving at the same chat from a link or after a reload rebuilt the whole thing instead, so one way in could take many times longer than the other on a conversation with thousands of messages. Both doors now render the same amount and show the same line above it.

- **While an answer is being written, Skales stops re-sending the whole conversation to itself three times a second.** Watching a running turn asked for the run and the entire conversation on every tick, even when nothing about it had changed - on a long chat that is megabytes a second going nowhere. It now asks whether anything moved and only fetches the conversation when it did. What you see while a turn runs is unchanged, at the same speed.

- **A long history stops re-reading itself every time the app starts.** Listing your conversations read every session file whose timestamp had moved, in full, however old the conversation was - so a backup, a sync tool or a migration touching a folder of months-old chats made the sidebar pay for all of them again on every launch. Conversations from the last two weeks are still read directly; older ones answer from the list Skales already keeps, and are opened once - the first time they are seen - and not again. The list itself is unchanged: every conversation you have ever had still has its row, in the same order, with the same words on it.

- **The model picker in the Code window scrolls, at any window size.** It held a scrolling list inside a scrolling box, and the box measured itself against the whole window height rather than the room around the button it hangs off - so in a short window the wheel landed in whichever of the two the pointer happened to be over and the list stayed where it was. There is one scroller now, as tall as the gap under the button, and the menu opens upwards when that gap is the smaller one. The list also shows the whole catalogue instead of the first sixty entries, and the arrow keys walk it, so the last model is reachable with the keyboard alone.

- **The wheel scrolls the menu you opened, not the row underneath it.** The chip row along the bottom of the Code window scrolls sideways, and it treated a mouse wheel anywhere in it as a sideways scroll - including over a menu that had opened out of it. So turning the wheel over the model list moved the row beneath the list and left the list itself exactly where it was. A menu opened over that row now answers the wheel itself.

- **A short Code window is laid out for a short window.** Every rule in the window's stylesheet asked how WIDE the frame was and none asked how tall, so a window dragged down to a strip was given the answer written for a narrow one: the review panel and the preview stacked under the transcript, three boxes sharing a hundred pixels each. A short window keeps its columns now. Narrow and short at once, a panel opens over the body instead - the transcript keeps its width and the composer stays where it was - and two open panels share that space down the middle. The title bar's own buttons bring them back, the way the history column already worked.

- **Nothing in the Code window's title bar is squeezed under its own icon.** In a narrow window every button in that row shrank: the history button was drawn at twelve pixels instead of twenty-eight, with its icon painted over the neighbour, and the end of the row ran past the edge of the window frame entirely. Buttons keep their size now and the row itself gives way.

- **A path that starts with an underscore is shown the way it is written.** A long file path is shortened from the left so its end stays readable, and that had the side effect of moving a leading underscore or slash to the other end: `_koordination/NUMMERN.md` was drawn as `koordination/NUMMERN.md_`. Four places in the Code window did it - the folder in the status bar, the file rows of the review panel, the header of an opened document, and the file suggestions under `@`.

- **The WhatsApp Web build is something you can choose.** Under Settings, Integrations, WhatsApp there is now a field for it, with the builds this machine has stored offered by name and the ones that carried a file marked. Left empty, WhatsApp picks the build exactly as it always has. Filled in, the connection stays on that build, so a bad release is a minute of your time instead of a wait for an update. The stored builds also stop piling up: Skales keeps the recent ones and whatever a fallback might still need, and clears out the rest - they were adding up to hundreds of megabytes of pages nothing would ever ask for again.

- **The menu behind the tray icon lists the same places the sidebar does.** It was still the list from before the sidebar was rebuilt: no way to the Dashboard at all, and Studio and the Cockpit offered whether or not you had switched their add-on off - a menu pointing at a page the navigation had put away. The Dashboard and Skales Code are in it now, and the optional entries follow the same switches the column does. A machine that has never opened the Add-Ons page still sees all of them.

- **A calendar you never connected asks you to connect one, instead of showing a failure.** The dashboard tile and the Calendar page both drew a red card with a Retry button on a machine where no calendar had ever been set up - and retrying cannot set one up. Sending mail had the same gap. All of them now say which of the two things happened: never connected gets the way to Settings, and a server that refused gets the failure and the reason.

- **A plugin the agent wrote says which model wrote it.** The shelf could not answer that question, because nothing on disk carried it. A plugin built in a conversation now records the model that built it and shows it on its row; it is recorded once, so a plugin you have edited since still names what drafted it, and a plugin you typed in yourself or imported says nothing rather than guessing.

- **An untouched installation no longer opens Settings on a provider that needs a key.** Skip the setup, go to Settings and Providers, and the screen preselected OpenRouter - a provider that cannot answer a word without an API key - so the first thing a new machine asked for was a key it had no reason to have. The grid now opens on the same pick the setup screen would make: Skales IQ, which needs no key at all, for as long as nothing else is set up. A provider that can actually answer wins, always - one with a key, or one of the local runtimes that needs none - and the install default left standing with no key at all does not count as a choice.

- **Right-clicking a picture in a conversation offers the picture.** It offered the message: Copy, Rewrite, Quote, Delete - everything about the text around the image, and no way at all to keep the image. Saving it, copying it, opening it in Studio and flagging it are now the first entries in that menu, with the message entries below them, unchanged and in the same order as before. It works for every picture a conversation can hold - one Skales drew, one you attached, one fetched from the web - and the browser and the installed app now show the one menu instead of two different ones.

- **A live HTML preview you have scrolled past stops running.** Every preview in a conversation kept its page going - timers, animations, whole little programs - long after it had left the screen, and a long chat can hold dozens of them, all of them drawing at once. A preview now runs only while its row is anywhere near the view, and it starts again a screenful before you reach it, so scrolling back finds it already alive. Hiding a preview by hand works exactly as before, and nothing about the card changes when you scroll past it.

- **Team rooms come back on their own in the installed app, not only in a development build.** Every time Skales started its remote bridge, the step that reconnects your team rooms failed before it began: the packaged app resolved it to something that no longer carried the routine, so rooms stayed dark until the screen was opened by hand, and a phone that had been paired to one could drop its connection. The step is wired directly now, and it still runs ahead of the remote-access switch, because a room is not a paired device and nothing else would bring it back.

### Changed

- **A long conversation is trimmed instead of retold.** When a conversation grows past the point where Skales has to shorten it, it has always written a summary of the older part - which meant your own sentences came back paraphrased. With a decision model switched on it now does something better: it goes through the older tool steps one by one, asks which of them still carry weight, and simply sets aside the ones that do not. Everything you and Skales SAID stays word for word, in the order it was said, and the most recent part of the conversation is never touched at all. The conversation says which of the two happened and how many steps it kept. The Auto-Compact slider under Memory Mode still decides when any of this begins, and switching it off switches this off with it. Without a decision model - or whenever trimming would barely save anything - the summary runs exactly as it always has.

- **The Code window now wears the theme you picked, and keeps its own shape.** Skales Code carried a fixed palette of its own, so a window opened under Classic or Flat was painted in the green of a theme you were not using, and switching theme changed everything except this window. It now takes its colour from whichever of the three themes Skales is set to: the page and the cards are that theme's own, the titlebar and the history column are the two steps between them, and the text is the theme's three text tones, each walked to a readable contrast against the hardest surface it is painted on rather than trusted to be readable. Where the theme takes the accent you picked in Settings, so does the window, and where it does not - Classic paints its own - the window follows that too, instead of showing an accent the rest of Skales refuses. What does not change is the shape: the type, the sizes, the spacing, the corners, the diff and the terminal block are the developer surface and stay exactly as they were. The terminal block stays dark in both light and dark, but takes the hue of the page, so it reads as part of the same room. A theme switched while the window is open arrives there without a reload, including a switch between two dark themes.

- **A browsing run that reaches something binding now asks you and then carries on, instead of stopping there.** When Skales worked through a goal on a page by itself and the next step would have published, sent, bought, signed in or deleted, the run ended at that step and handed the page back - so the job was then finished by hand, one click at a time, with each click judged on its own. That step is now put in front of you as the ordinary approval card, with what has already been done and what would happen next. Approve it and the same run carries that step out and goes on towards your goal from there; decline and nothing was clicked. The page is read again before the approved step is taken, and the control is found by the name you were shown, so a page that changed while the question was waiting says so rather than pressing something else. A run held this way survives Skales being restarted, and one approval covers one step - a second binding step asks again.

- **Clicking by reference number no longer slips past the questions clicking by name would raise.** Skales can address an element on a page either by describing it or by the short reference it was given when the page was read. The reference carries no words, and the checks that tell a purchase or a publication from an ordinary keystroke read words - so the same button asked before it was pressed when it was described, and did not when it was referenced. The element's own name is now looked up and used for that judgement, whichever way it was addressed. On top of that, before a reference is used for something binding, it is checked against that name, and a reference that turns out to point somewhere else is refused with the reason instead of clicked.

- **The page listing points at the tool that does the job, not at the one that does one step of it.** Every page Skales read ended with a line suggesting a single click by reference, which made a six-step goal into six unguided clicks. Where the multi-step run is available, that line now names it as the way to work the page and keeps the single click for fine work. Installations without a decision model see the sentence they saw before.

- **The Decisions setting says what it is answering today.** It described a fast model for yes-or-no questions without saying where those questions come from; it now names them - which element a description means, whether a page has reached your goal, and whether the next step would be binding.

- **The browser shows what the run is doing, instead of visiting the same address a second time.** While Skales drove a page, the browser surface followed it by loading the run's ADDRESS into its own view - a separate visit with its own sign-in, an empty form where Skales had typed, and nothing moving at all for the many steps that happen on one address. It now shows the pictures the run itself takes after every step, each with the line that says what the step was, and your own browsing is left untouched underneath; a button puts it back in front. The pictures are capped, they are cleared when the run ends, and the surface says plainly that it proves nothing - whether a step landed, and whether anything was published, is still said in the conversation and nowhere else.

- **The browser's first-open notice covers the browser, not the whole window.** The notice you see the first time you open the browser was drawn over the entire window rather than over the surface it belongs to. Wherever that surface sits - its own page, the sidebar, or the panel in the Code window - the notice now fills exactly that.

- **In the Code window the browser is a panel beside the transcript, not a window over it.** It had been a full-screen dialog, so during a run you could see the browser or the conversation but never both. It is a panel now, in the same split the review and preview panels use, and all three can share the space. The button for it still appears only when the Browser Control add-on is on.

- **The days in the conversation column fold away, and stay folded.** A long history meant scrolling past every day to reach the one you wanted. Each day heading is now a lid: click it and that day folds shut with a count of what is behind it, and it is still shut the next time you open Skales. Pinned conversations sit above the dates as before and do not fold - they are the ones you put there on purpose. At the foot of the list there is now a way through to the full history page, where the search and the filters are.

- **Iris now wears the theme you picked, and its particles carry your accent.** The voice window used to paint itself off-white or black whatever the rest of Skales looked like, so a Classic or Flat page ended at the edge of it and a colour you chose never reached it. It reads the same page, card, ink and hairline colours as every other window now, in all three themes and in both light and dark, and the eye's particles take the accent colour - lifted away from the background far enough to stay clearly visible when the accent and the page sit close together. The recalculation happens when you change the theme, never while the eye is drawing, so nothing about how it moves has changed. Space Grotesk, the face Iris is lettered in, stays as it was.
